# CLIProxyAPI token usage source

The site's token data now comes from the local CLIProxyAPI service. The browser still reads `https://web.sambolgert.com/data/token-usage.json`; changing the source did not change the website's JSON contract or require a site rebuild. The former LiteLLM daily aggregates remain in a separate historical table so the 365-day view includes usage from before the migration. Sources: `/home/sbolgert/workspace/cliproxyapi-service/MIGRATION.md`, `/home/sbolgert/workspace/cliproxyapi-service/scripts/usage.py`, and [site parser](../src/data/token-usage.ts).

## Collection and persistence

`cliproxyapi-usage.service` runs `scripts/usage.py collect`. The collector authenticates to the loopback CLIProxyAPI listener at `127.0.0.1:8317` with the private management key, subscribes to the RESP `usage` channel, then drains `GET /v8/management/observability/usage/queue?count=10000` with a management Bearer token. It reconnects after a connection error. The management key is distinct from the client API key and must stay out of the public snapshot. Sources: `/home/sbolgert/workspace/cliproxyapi-service/systemd/cliproxyapi-usage.service`, `/home/sbolgert/workspace/cliproxyapi-service/scripts/usage.py`, [upstream RESP handler](https://github.com/router-for-me/CLIProxyAPI/blob/8ef43e4df3b216a42493105d31c2873b69191473/internal/api/redis_queue_protocol.go), and [upstream v8 management routes](https://github.com/router-for-me/CLIProxyAPI/blob/8ef43e4df3b216a42493105d31c2873b69191473/internal/api/server_management_v8.go).

The collector stores one row per `execution_id` in `state/usage.sqlite3`; duplicate IDs are ignored. It uses SQLite WAL mode and full synchronous commits. Records retain the local date, model, provider, prompt tokens, completion tokens, request count, and cache-read tokens. The collector does not copy prompts, response bodies, keys, headers, IP addresses, or account identities into SQLite or the public JSON. The service configuration enables usage statistics and gives CLIProxyAPI's in-memory queue a 3,600-second retention period. Sources: `/home/sbolgert/workspace/cliproxyapi-service/scripts/usage.py`, `/home/sbolgert/workspace/cliproxyapi-service/config/config.yaml`, and `/home/sbolgert/workspace/cliproxyapi-service/MIGRATION.md`.

This is best-effort collection. CLIProxyAPI's queue is in memory, and its management endpoint **pops** queued records. A proxy restart can lose records that have not reached SQLite. A second queue consumer can also remove records before this collector reads them. Requests outside this proxy are absent. Sources: [upstream queue endpoint](https://github.com/router-for-me/CLIProxyAPI/blob/8ef43e4df3b216a42493105d31c2873b69191473/internal/api/handlers/management/usage.go) and `/home/sbolgert/workspace/cliproxyapi-service/MIGRATION.md`.

## Token accounting

For a complete schema-v2 `token_breakdown`, the collector uses `input.total_tokens` as prompt tokens, `output.total_tokens` as completion tokens, and `input.cache_read_tokens` as cache reads. Cache reads are already part of input tokens; reasoning tokens are already part of output tokens. The displayed total is prompt plus completion, so neither bucket is added twice. If the complete v2 breakdown is unavailable, the collector falls back to the legacy `tokens` fields. Sources: `/home/sbolgert/workspace/cliproxyapi-service/scripts/usage.py` and [upstream accounting contract](https://github.com/router-for-me/CLIProxyAPI/blob/8ef43e4df3b216a42493105d31c2873b69191473/sdk/cliproxy/usage/accounting.go).

Events are bucketed by `America/Chicago` date. The exporter covers the last 365 calendar days, joins imported LiteLLM history with CLIProxyAPI events, and groups by date, model, and provider. It maps CLIProxyAPI's `codex` provider to the historical `chatgpt` label and `openai-compatible-openrouter` to `openrouter`. A counted request has a positive prompt-plus-completion total. Sources: `/home/sbolgert/workspace/cliproxyapi-service/scripts/usage.py` and `/home/sbolgert/workspace/cliproxyapi-service/MIGRATION.md`.

## Publication and site contract

`token-usage-export.timer` runs the exporter at boot and every 15 minutes. It writes a temporary JSON file, syncs it, and atomically replaces `/home/sbolgert/workspace/web-server/public/data/token-usage.json`. The snapshot has `generatedAt`, daily totals and model rows under `days`, and aggregate `byModel`, `requests`, `cacheReadTokens`, and `models` under `totals`. The web server permits CORS from `https://sambolgert.com` and sends `Cache-Control: no-cache`. The site's client fetches and validates the file at runtime. Sources: `/home/sbolgert/workspace/cliproxyapi-service/systemd/token-usage-export.timer`, `/home/sbolgert/workspace/cliproxyapi-service/scripts/usage.py`, `/home/sbolgert/workspace/web-server/nginx/default.conf`, [site parser](../src/data/token-usage.ts), and [site client](../src/scripts/token-usage-client.ts).

For operational checks, run `python3 scripts/usage.py status` or `systemctl --user status cliproxyapi-usage.service token-usage-export.service` from the service checkout. To publish immediately, run `systemctl --user start token-usage-export.service`. The `status` command reports row counts and collector health without printing credentials. Source: `/home/sbolgert/workspace/cliproxyapi-service/scripts/usage.py` and `/home/sbolgert/workspace/cliproxyapi-service/MIGRATION.md`.
